### 3.1 Critical bug found + fixed (2026-09-23, later session) — Tailwind utilities were silently no-ops site-wide on Admin

**Root cause**: `src/styles/global.css`'s `* { box-sizing:border-box; margin:0; padding:0; }` reset is a plain unlayered rule. Tailwind v4 (`src/admin/layout/styles/globals.css`) wraps everything it generates in `@layer theme, utilities`. Per the CSS cascade-layers spec, **an unlayered rule always beats a layered one, regardless of specificity or source order** — so every single Tailwind spacing/box-sizing utility used anywhere in `AdminApp.tsx` (`md:ml-[60px]`, `px-10`, `py-4`, everything) was being silently zeroed. This is why `md:ml-[60px]` never pushed content past the nav rail — confirmed live (owner screenshot: header/nav text clipped by the sidebar) and reproduced/verified via a real logged-in session (`getComputedStyle` showed `margin-left: 0px`, `padding: 0px` despite the classes being present and applied).
**Fix**: wrapped just that one reset in a named `@layer legacy-reset { ... }` in `global.css`. Since it's the first `@layer` the page encounters (loads in `<head>`, before Tailwind's JS-injected stylesheet on the Admin route), this registers `legacy-reset` first in the page's layer order — Tailwind's `theme`/`utilities` layers land after it, so `utilities` now correctly wins. Verified: no effect on the public site (nothing else there uses `@layer`, so the cascade result for every non-Admin page is byte-identical to before — reasoned through and live-checked). Verified live with a real provisioned owner login: sidebar overlap gone on both Preview/Users and Character/Skin CMS routes, `header`'s `px-10 py-4` now computes real padding, Character CMS tile grid renders correctly.
**Also**: the `data-nav-expanded` sidebar-expand state that `WHMX_APP_ARCHITECTURE.md`-adjacent CSS references (`.app-nav-toggle-btn`, `[data-nav-expanded="true"]` rules in `style.css`) is **dead/unreachable** — no toggle button element exists anywhere in the current HTML/JS, so the nav rail never actually expands wider than its collapsed 60px on any route, public or Admin (confirmed via full-codebase grep). The public site's own "Compact Overlay Rail" cascade layer (`src/style.css` ~6100) also hardcodes `.app-layout` to a fixed 60px `!important` regardless of that attribute. So AdminApp.tsx's fixed `md:ml-[60px]` already matches the one real, reachable state — no further "reserve extra space for an expanded sidebar" work is applicable unless a real expand interaction gets built later (separate, unscoped feature).

## Anti-slop checklist (huashu principles → this codebase)

- **No new colors** — every color must resolve to an existing `--*` token in `src/styles/tokens.css`. If a direction seems to need one that doesn't exist, reuse an existing rarity/accent token creatively or flag it to the owner as a token-addition proposal — never hardcode a new hex value inline.
- **No decorative icons** — don't add icon sets to "modernize" nav tabs/buttons unless an icon replaces genuinely redundant text.
- **No gradient slop** — no `linear-gradient` on cards/buttons/headers "for depth"; the existing flat dark-charcoal/antique-gold surfaces + `--shadow-pop` are the established depth language.
- **No generic rounded-card-with-left-accent-border** — if list rows need state differentiation, match the vocabulary `.character-cms-tile`/`.character-cms-skin-card` already use, don't invent a new pattern.
- **Real content only in review artifacts** — Phase 2 screenshots must show real character/skin/user data from the dev DB, seeded with representative entries if sparse, never fabricated placeholder text.
- **No silent radius/spacing normalization** — any such change in a direction must be called out explicitly in that direction's writeup, per the locked invariant at `docs/WHMX_APP_ARCHITECTURE.md:219`.
